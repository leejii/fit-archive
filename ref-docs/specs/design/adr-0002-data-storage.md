# ADR-0002 · 데이터 저장: Supabase (클라우드 동기화)

## 맥락
- 장기 사용 · **데이터 영속성/이식성**이 핵심 요구.
- 폰·PC 두 기기에서 같은 데이터를 봐야 함(동기화 필요).
- 사진은 용량이 커서 텍스트 메타데이터와 분리 저장이 유리하다.

## 결정
Supabase를 사용한다.
- 메타데이터 = **Postgres**
- 사진 = **Storage**
- 사용자 식별 = **Auth**(이메일 매직링크)

## 근거
- 클라우드 DB로 기기 간 자동 동기화를 확보한다.
- Postgres(관계형) → 스키마가 명확하고 쿼리·확장이 쉬워 유지보수성이 높다.
- 사진을 Storage로 분리 → 백업·전송 효율이 좋고 메타/블롭 결합도를 낮춘다.
- 무료 티어로 개인 규모에 충분하다.

## 영속성·이식성 안전장치
- 서비스 잠금(lock-in) 위험 완화를 위해 **전체 내보내기(JSON/CSV)를 제품 기능으로 둔다**(→ 데이터 모델이 아닌 기능. `adr-0003-v1-scope` 참조).
- Postgres는 표준 SQL → 언제든 덤프/이전 가능.

## 고려했으나 보류
- **로컬 우선(IndexedDB/SQLite) + 수동 내보내기**: 소유·영속성은 최상이나 기기 간 동기화가 수동이라 사용 시나리오와 상충.
- **하이브리드(로컬 + 클라우드 백업)**: 이점은 있으나 초기 구성 복잡도가 커 V1 범위 밖.

## 영향
- 로그인 주체가 생긴다(개인용, 가벼운 매직링크).
- 각 레코드가 user에 귀속 → Supabase RLS(행 수준 보안) 규칙 설계 필요.
